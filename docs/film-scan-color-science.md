# 胶片扫描：去色罩、特性曲线与迫冲/减冲

## 1. 检查结论与适用范围

当前实现完成了通用负片转换流程修复，尚未按胶卷型号完成曲线数字化和扫描标定。填写不同的 `filmStock` 名称，不代表已经使用对应型号的完整特性曲线。

原实现存在三条不一致的转换路径：单元测试直接对编码 RGB 取对数；Sharp 备用路径简单反相；生产 FFmpeg 路径在线性化后将净密度除以 2.4。后者输出的是归一化密度，不能等同于还原曝光。Sharp 连续 `linear` 调用还会覆盖之前的参数，使曝光、白平衡或色阶被后续设置抵消。

当前生产 FFmpeg、Sharp 备用路径和 `demaskRgb` 采用同一个模型；生产滤镜生成与数值计算同属 [film-negative.cjs](../apps/api/src/film-negative.cjs)。16 位实际输出集成测试覆盖两条路径，避免只验证独立数学函数。

## 3. 密度与曲线的使用原则

Log H Ref 是对数曝光参考，不是片基密度、扫描 gamma 或特性曲线斜率，不能填入当前 `NEGATIVE_GAMMA`。

1. **去片基与校曲线是两件事。** 每卷采样可消除部分片基加灰雾偏置；要让多个灰阶都中性，还需每个色层各自的 D-logH 反函数，必要时加入扫描仪色彩矩阵。只校准一个灰点不能证明暗部和高光也中性。
2. **0.6 没有获得跨胶卷的官方数值验证。** 当前 `NEGATIVE_GAMMA` = 0.6 是通用近似，已查阅的资料不能自动使这个常量变成厂商标定值。目前未从图表提取并拟合三色层曲线，也未建立实测型号 LUT。
3. **测量体系必须匹配。** 厂商 Status M 密度不是 sRGB 码值。当前处理是色彩管理后 RGB 的有效密度近似；严格光学密度需考虑扫描光源、感光通道、暗电平、杂散光与染料光谱。不能仅由 D 推算 10^(-D) 后直接当作界面 `maskRgb`。
4. **区分曲线类型。** D-logH 用于曝光与反差关系；光谱染料密度描述吸收与串扰；光谱敏感度描述曝光响应；MTF 描述空间清晰度。不能拿 MTF 或光谱敏感度代替反转曲线。
5. **按版本、冲洗工艺和扫描条件建档。** 可追溯的型号校准至少要记录型号/版本、工艺、迫冲减冲、测量体系、RGB 曲线采样点、曝光参考、片基取样及扫描标定状态。ECN-2 的曲线不能无条件用于同款电影卷的 C-41 交叉冲洗。

## 4. 当前算法实现

### 4.1 输入约定

经现有色彩管理路径转换的 sRGB 扫描负像；`maskRgb` 也采用 sRGB 编码。FFF/3F 沿用现有实验性解码支持。

### 4.2 转换步骤与参数

1. 对扫描像素与片基同时做 sRGB 逆传递函数，得到线性透射率 T 与 Tb。
2. 计算净密度 D = max(0, log10(Tb / T))，相当于减去片基加灰雾密度。
3. 使用通用直线段斜率 gamma = 0.6，得到相对曝光 E = 0.02 × (10^(D / gamma) - 1)。减去曝光底值使片基本身落在黑位。
4. 采用 E / (1 + E) 软压缩高光，再显式编码回 sRGB。
5. 合并曝光、白平衡、对比度和黑白场为一次仿射调整，随后保留饱和度与用户高光控制。迫冲/减冲不参与后期曝光计算。

0.6、0.02 和高光压缩是本项目通用显影近似与显示映射的工程选择，不是 Kodak 或 Fujifilm 指定的标定值；没有对趾部、肩部及三色层差异进行实测拟合。该算法提供中性起点，而非绝对场景色度还原。

### 4.3 位深与渲染一致性

FFmpeg 明确在 16 位 planar RGB 上计算，避免 `geq` 隐式协商格式导致浮点值范围混淆。像素取样采用 `nearest`，避免边界像素被双线性采样替换。Sharp 备用路径通过 16 位查表转换。PNG 16 位输出明确使用 `rgb16`。

### 4.4 自动片基与预览

自动片基采样比较裁切框沿片带方向两侧的帧间空隙与框内边缘环。先排除非有限值、通道剪切和近白漏光像素，再以 0.86 分位数寻找平台、按全通道容差保留样本并重估 RGB。近白漏光暂以最高通道不低于 0.8、最大与最小通道差小于 0.08 判断；这些是工程阈值，可能排除极浅色罩，不能替代扫描标定。支持率仍以过滤前的总采样数为分母，避免少量残留像素得到虚高置信度。帧间空隙置信度达到 0.85 时优先使用该候选，不让更均匀的画面暗部覆盖它；没有达标空隙时保留边缘环备用路径。

整卷汇总先计算逐通道中位数，要求超过半数估计在每个通道上均与中心相差不超过 0.04，再仅汇总这些一致样本。偶数样本取中间两项平均值；两帧明显冲突、两组势均力敌或没有多数共识时返回空结果，交由现有预设／通用基准回退路径处理。单个有效估计仍保持兼容。0.04 是归一化扫描 RGB 的启发式容差，不是色度误差标准。分析与重新预览共用该聚合，最终片基确定后重绘使用不同片基的早期预览。均匀有色主体、裁切误差和扫描条件差异仍可能造成误判。

审核时切换自动模式会清除旧 RGB 与手动取样点并重新解析片基；切换预设模式按扫描仪和胶卷型号查找片基。预览与整卷保存共用解析逻辑，已保存的预览与导出使用同一参数快照。直接修改手动 RGB 会清除取样点，避免旧坐标覆盖输入；仍保留取样点时继续按所选原档采样。自动模式仅调整影调时可复用已保存片基，避免重复分析。

### 4.5 迫冲/减冲字段

正值为迫冲，负值为减冲，0 为正常冲洗，单位为档，保留原有 -5～+5 范围与 0.5 步长。存储字段 `pushPull` / `push_pull` 保持兼容。

该字段记录冲洗条件，不参与后期曝光计算。

## 5. 使用建议与限制

- 优先在未曝光、已经冲洗的干净片边手动取样；避免齿孔、片夹、灰尘和扫描灯直射区域。
- 扫描仪输出应为保留负像的扫描。已被 SP-3000、Noritsu 等软件反转成正像的 JPEG/TIFF 不应再走负片反转；当前胶片类型字段不单独表达输入正负像，仍需用户确认原档。
- 无 ICC、扫描软件局部调整、混合光源、染料串扰以及迫冲导致的色层反差变化，不能仅靠片基取样消除。严格校色需同一扫描条件的灰阶/色卡以及每色层或矩阵标定。
- gamma 近似对彩色负片适用；黑白负片、反转片保留其既有处理。没有用彩负资料推定它们的实测曲线。
- 原有已导出照片不会自动重写；重新预览或导出后才应用新处理。

## 6. 验证方法与结果

以下为算法修改时的验证记录，不代表文档整理后重新执行了这些检查。

### 6.1 算法验证

- 合成物理中性灰阶：线性片基透射率乘以 10^(-D)，再编码成扫描值；不再把 sRGB 数值直接相乘冒充光学衰减。
- 真实 FFmpeg 与 Sharp 16 位输出对照，逐通道误差小于 0.0001（归一化值），包括片基、灰阶和高密度区域。
- 曝光与色阶组合、默认高光控制下曝光是否生效、片基置信度、迫冲/减冲正负及小数值回归。
- 自动片基识别：帧间空隙优先于画面暗部、帧号油墨等暗污染不偏移估计、近白去饱和亮区被拒绝而低饱和度但真实带色性的色罩可用、横竖扫描条带对称、整卷逐通道中位数聚合对单帧离群不敏感。
- 未使用真实胶片灰卡/色卡完成视觉与色度标定；合成中性测试不能证明任意实拍扫描均达到特定 Delta E。

API 52 项测试、前端 62 项测试、TypeScript 检查通过。使用项目本地配置在独立临时目录完成 Next.js 生产构建；未部署或重启服务。浏览器运行时没有可用实例，未进行实机交互验收。全项目 UI 静态审查报告位于 `tmp/film-scan-ui-audit.json`，记录了 29 项现存的设计契约、表单和滚动条规范问题；这些全站问题不属于本次胶片处理与单字段文案修改范围。

## 7. 按型号校准的后续工作

后续若实现按型号的定量反转，需要先把曲线数字化并记录读图误差，再用同一扫描条件下的真实灰阶验证中性与单调性；没有实测依据的型号应明确回退到通用模式。官方图表可作为建模起点，不应因其不是扫描仪 LUT 就停止查阅。

查阅资料、数字化曲线与完成扫描标定属于不同阶段，应分别记录完成状态。

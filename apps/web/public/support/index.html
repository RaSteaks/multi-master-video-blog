从文件，
到屏幕。

一帧画面要走两条线：播放线把文件送到解码器，色彩线让数值获得颜色与亮度的含义。

两条线在同一张网上并行，在探测、封装、解码和显示四站换乘；设备不支持时，播放器改走 SDR 支线上的兼容母版。向下滚动沿线乘车，向上回看，也可以点线路图上的站直接到达。

    全程 12 站

    P1原始文件先完整抵达

    播放线 · 服务器上传端 / 接收服务

    浏览器按 1 MiB 分块传输，支持断点续传。所有分块确认后，任务进入后台处理队列；上传传输本身不重压视频。

    单文件按所选母版类型进行后续验证。一次加入 HDR 与 SDR 两份视频时，服务端根据流元数据识别两者，无需按文件顺序选择。

    输入
    视频文件、母版包或 HLS 包
    输出
    保存的源文件与后台处理任务

    P2从媒体内部确认 HDR 信息

    播放线 · 服务器FFprobe / 色彩校验与 C1 同站换乘

    读取编码配置、像素格式、原色、传递函数、矩阵和范围。对 PQ、HLG 或 Dolby 视频，再抽样解码开头 32 个 packet 范围内的帧，补查静态 HDR 与 Dolby 帧元数据。

    Dolby Vision 还扫描完整 HEVC 码流中的 RPU，记录数量与 SHA-256。只有 sidecar 文件或“存在 RPU”的标志，不能通过验证。

    输入
    源文件与嵌入式元数据
    输出
    源色彩信息、RPU 完整性记录

    C1先确定数字代表什么

    色彩线 · 服务器源文件 / 色彩描述与 P2 同站换乘

    原色定义色域，传递函数定义信号与光的关系，矩阵和 full / limited 范围定义分量如何解释。HEVC 或 10-bit 本身不足以确认 HDR；宽色域也可以用于 SDR。

    HDR10 的 Mastering Display 描述母版监视器的原色、白点与亮度范围；MaxCLL / MaxFALL 描述内容峰值与最大帧平均亮度。它们与视频编码原色是不同的信息。

    输入
    像素格式、色彩标记与 HDR 元数据
    输出
    可验证的信号解释规则

    P3保留 HDR 视频，整理成 HLS

    播放线 · 服务器FFmpeg / 媒体发布与 C2 同站换乘

    普通 HDR 母版使用 -c:v copy 复制视频码流，音频转 AAC。生成 master.m3u8、媒体列表、init.mp4 和 fMP4 分段；分段目标 4 秒，实际切点受关键帧约束。

    输出会重新探测，对照色彩字段、静态元数据及 Dolby RPU 数量与哈希。验证通过并完成媒体发布后，母版才标记为 ready。每份 HDR / SDR 母版拥有独立的播放地址。

    输入
    已验证的 HDR 母版
    输出
    HLS 文件、播放声明与验证报告

    C2让色彩信息随码流抵达播放器

    色彩线 · 服务器封装 / 信号完整性与 P3 同站换乘

    HDR 复制封装会比较输入与输出的色彩字段和静态元数据。Dolby Vision 还要求 RPU 的数量与哈希保持一致。

    信息有三层：数据库用于展示和选源；HLS 的 CODECS / VIDEO-RANGE 用于声明播放要求；媒体内部的配置、色彩标记、SEI 或 RPU 才随视频进入解码和显示链路。数据库标签不会替代文件中的元数据。

    输入
    源色彩信息与 HDR 码流
    输出
    保留色彩信息的 HLS 媒体

    C6生成经过映射的 SDR 母版

    SDR 支线 · 服务器上传后处理 / 独立兼容版本

    新项目上传 HDR 且未随附 SDR 时，会尝试使用 libplacebo / Vulkan：动态峰值检测、BT.2390 tone mapping 与 perceptual gamut mapping，将亮度和宽色域映射到 BT.709 limited、8-bit H.264 / AAC。

    支持的单层 Dolby Vision 会启用 apply_dolbyvision=true 使用嵌入 RPU。转换后去除 HDR 元数据，并分别验证 SDR 文件与 HLS。生成失败仍保留 HDR；已有项目不自动补生成，手动 SDR 也不会被替换。

    输入
    已验证 HDR 或 IMF 转出的 HDR10
    输出
    独立、已验证的 SDR 播放版本

    P4按具体配置选择可用母版

    播放线 · 网页播放器前端播放器 / MediaCapabilities

    先检查显示环境是否报告 HDR，再读取候选母版首个 HLS variant 的 CODECS、VIDEO-RANGE、分辨率、帧率和带宽，连同色域及传递函数查询 decodingInfo()。

    只有 supported 与 smooth 同时为真才自动选 HDR。支持的 HDR 中优先指定默认母版，再按 Dolby Vision、HDR10、HLG 排序。单次能力查询限时 1.5 秒，整体选源限时 5 秒；没有候选通过或整体超时时，如有已验证 SDR 就选用它。手动选择优先。

    输入
    ready 母版、HLS 声明、设备能力报告
    输出
    适合当前播放环境的母版地址

    P5把压缩样本解码为视频帧

    播放线 · 网页播放器 → 浏览器与系统Shaka / 浏览器 / 操作系统与 C3 同站换乘

    HDR 播放在支持原生 HLS 的浏览器上优先走原生路径。其他情况下，Shaka 获取并缓冲分段，经 MediaSource Extensions（MSE）交给浏览器媒体管线。

    浏览器读取初始化信息和视频样本，调用平台解码器。是否使用硬件加速由浏览器、系统与设备决定；通用 HEVC 解码能力不能直接证明支持 Dolby Vision。

    输入
    初始化分段、压缩视频样本和时间戳
    输出
    视频帧及后续色彩处理所需信息

    C3恢复图像样本，正确解释电平

    色彩线 · 浏览器与系统解码 / 分量重建与 P5 同站换乘

    解码器恢复视频样本。对典型 Y′CbCr HDR10 / HLG 视频，色度采样位置、矩阵系数以及 limited / full 范围参与后续重建和转换。错误解释范围可能造成黑位抬高或高光裁切。

    这些是概念上的处理环节，平台可能合并执行。Dolby Vision Profile 5 需要对应的 Dolby 处理路径，不能直接套用普通 HDR10 的解释方式。

    输入
    解码后的分量样本、矩阵与范围
    输出
    进入亮度与色彩处理的图像信号

    C4PQ 与 HLG 使用不同的光信号关系

    色彩线 · 浏览器与系统传递函数 / 亮度解释

    PQ（SMPTE ST 2084）使用绝对显示亮度的编码关系；码值对应的目标亮度不等于当前屏幕必然达到的亮度。HLG（ARIB STD-B67）使用相对场景信号关系，最终显示还涉及系统变换与显示条件。

    播放器查询能力时会明确传入 pq 或 hlg。网站没有在 JavaScript 中逐帧施加自定义 LUT；这些媒体处理由浏览器与平台管线承担。

    输入
    视频信号及 PQ / HLG 标记
    输出
    具有正确亮度含义的图像

    C5适配屏幕可呈现的色彩与亮度

    色彩线 · 浏览器与系统系统色彩管理 / 显示设备与 P6 同站换乘

    浏览器与系统结合源色域、HDR 信息和目标显示能力，执行所需的色域与亮度映射。支持 Dolby Vision 时，平台需要正确处理其动态元数据。

    屏幕峰值亮度、系统 HDR 设置、显示配置和连接方式都可能影响结果。能力 API 是选择信号，ready 是服务端验证状态；两者都不代表亮度实测、显示校准或 Dolby 参考渲染认证。

    输入
    图像、HDR 元数据与目标显示条件
    输出
    经过平台处理的屏幕画面

    P6输出画面，保留可用的退路

    播放线 · 浏览器与系统显示管线 / 播放器恢复与 C5 同站换乘

    系统结合色彩信息、显示能力和当前设置完成合成与输出。HDR 加载或解码出现致命错误时，播放器优先选择与该母版关联的 SDR，其次选择其他已验证 SDR，并保留播放位置和播放意图。

    SDR 再失败时显示错误与重试入口，避免在 HDR / SDR 间循环。没有可用 SDR 时，自动选源可能无法继续；可手动尝试已有母版，或由作者补充 SDR。

    输入
    解码帧、显示能力或播放错误
    输出
    显示画面，或切换 SDR / 提示重试

    终点：屏幕。线路图只示意处理顺序与责任范围，不代表真实视频输出、耗时或亮度。

    读懂元数据

    编码、色域和动态范围，分别回答不同的问题。右侧站号标出这个字段在哪些站被读取、校验或使用。

    codec / profile / level

    定义压缩编码及解码要求。HLS 的 CODECS 从实际输出配置生成，不只填写一个笼统的“HEVC”。

    相关站点：P2P3P4
    pix_fmt / bit_depth

    描述像素格式、色度采样和位深。当前实现优先读取显式位深，再从像素格式推断；未识别时使用母版类型默认值，因此并非独立的逐像素位深测量。

    相关站点：P2C1
    color_primaries

    编码原色，例如 BT.709、BT.2020 或 P3-D65。它定义信号的色域，不证明显示器能覆盖全部颜色。

    相关站点：P2C1P4C5
    color_transfer

    smpte2084 对应 PQ，arib-std-b67 对应 HLG。它决定亮度信号如何被解释。

    相关站点：P2C1P4C4
    matrix / range / chroma_location

    矩阵系数、编码范围和色度位置共同影响分量重建。相同码值在不同范围与矩阵下会得到不同结果。

    相关站点：P2C1C3
    SEI / DOVI / RPU

    HDR 静态信息、Dolby 配置与动态元数据。抽样解码检查帧附加信息；完整 RPU 扫描检查负载数量和哈希。

    相关站点：P2C2C6C5

    格式与兼容

    展开查看本站的接收、播放与转换条件。

    HDR10 PQ / 静态元数据

    当前上传校验要求 PQ、至少 10-bit、支持的 HDR 原色，以及 Mastering Display、MaxCLL / MaxFALL。普通 HDR10 视频复制封装，HLS 声明 VIDEO-RANGE=PQ。

    “至少 10-bit”是当前代码根据探测与推断值执行的规则；静态元数据存在且被保留，也不等于已验证原始调色与实际画面一致。

    相关站点P2P3

    HLG 相对场景信号

    当前校验要求 arib-std-b67、至少 10-bit 和支持的 HDR 原色，HLS 声明 VIDEO-RANGE=HLG。HLG 不采用与 HDR10 相同的静态元数据门槛，仍需要正确的色彩标记与显示处理。

    相关站点P2C4

    Dolby Vision 嵌入式 RPU

    当前浏览器交付路径接受单层 HEVC Profile 5、8.1（PQ / compatibility ID 1）及 8.4（HLG / ID 4），要求有效的嵌入式配置、基础层和可解析 RPU。增强层 / FEL 重建、Profile 7 与独立 sidecar 注入不在这条管线的支持范围内。

    Profile 5 使用 dvh1 标记；Profile 8 的 HLS 还提供 SUPPLEMENTAL-CODECS。自动检测必须得到具体 Dolby 编码配置的支持结果，普通 HEVC 支持不能代替。

    相关站点P2C2P4

    SDR 与 IMF 兼容版本 / 归档转换

    可以上传配对的 BT.709 SDR，或在符合条件的新项目中自动生成 SDR。自动转换为网页适配版本，不代表 Dolby 参考渲染或调色 trim 认证。

    支持的 RGB/PQ IMF 包通过 CPL / ASSETMAP 解析，转换为 HDR10 HEVC/AAC 播放版。原始包被保留；独立 Dolby 动态元数据只留在归档中，不应用到这个 HDR10 或由它生成的 SDR。

    相关站点P1C6

    当前自动 HDR 能力查询读取每份母版的第一个 variant，并接受 BT.2020 / P3-D65 原色。上传端也接受 DCI-P3，但前端不会据此自动选择 HDR。实际播放仍取决于设备与浏览器。

    播放遇到问题时

    从当前选中的母版开始排查。每条都标出线路上对应的站。

    HDR 屏幕为什么自动播放 SDR？

    检查系统是否启用 HDR、当前显示连接和浏览器是否支持该视频的具体编码配置。显示媒体查询只是一项前提，能力查询不支持、不流畅、不可用或超时，都会优先选择已验证 SDR。

    在视频页面展开播放信息（Show Info），查看当前母版、色彩标记和设备能力。也可手动尝试 HDR，但手动选择无法给设备增加解码能力。

    相关站点P4

    画面偏灰、偏色或高光异常，先看什么？

    核对当前是否已回退 SDR，再检查源文件的传递函数、矩阵与 full / limited 标记，以及系统显示设置。确认比较的是同一版本，并避免把普通截图当作 HDR 亮度证据。

    如果标签与原片信号不符，需要从导出与媒体校验环节修正。修改页面上的格式名称不会改变浏览器对码流的解释。

    相关站点C3C4C5

    Dolby Vision 失败后发生了什么？

    播放器会尝试关联的已验证 SDR，或其他已验证 SDR，并保留位置和播放状态。若 SDR 也失败，使用重试入口；若没有 SDR，需要作者补充兼容母版。

    相关站点P6

    切换母版会重新从头播放吗？

    播放器保存当前时间与播放 / 暂停意图，加载新母版后校正位置。切换完成以新画面到达为依据。HDR 画面不会被转换成 SDR 截图用作过渡，也不会把两个母版混合显示。

    相关站点P6

    说明对应本站当前实现。服务端验证关注媒体结构与元数据；屏幕亮度、色彩准确性和 Dolby 显示状态需要在目标设备确认。
